# 구현 계획

## 1. 저장소 및 설계 확정

- GitHub private 저장소 생성, main 브랜치 사용.
- 첫 버전은 WSL Linux x64에서 실행하고 Windows 측 로컬 Vault를 사용.
- npm scope와 배포 권한은 실제 배포 전에 확인. GitHub 인증이 npm 인증을 대신하지 않음.

완료 기준: README, 구현 계획, 기본 ignore 규칙이 원격 저장소에 존재.

## 2. Go 코어와 경로 처리

- Go 개발 도구 준비 및 module 초기화.
- 환경 감지, Windows/WSL 경로 입력, wslpath 호출 추상화.
- 존재 여부 및 읽기·쓰기 권한 검사. 없는 경로 생성은 동의 후 수행.
- XDG 사용자 설정에 기기별 Vault 경로 저장.
- 단위 테스트에서 파일 시스템과 외부 명령 실패를 검증.

완료 기준: 공백·한글 경로, 접근 불가 경로, 재실행 테스트 통과.

## 3. init 마법사와 Vault 준비

- 신규 Vault 생성 / 기존 Vault 연결.
- sessions/ 및 templates/ 준비.
- 기존 파일 보존, 변경 미리보기와 충돌 처리.
- 불필요한 플랫폼·동기화 기능은 추가하지 않음.

완료 기준: 반복 실행해도 기존 데이터가 변경되거나 사라지지 않음.

## 4. pi/Codex 수집 스킬

- 설치된 에이전트 버전의 스킬 발견 규칙을 공식 문서로 확인.
- 사용자 영역에 공통 capture 스킬 설치.
- 학습 질문, 배경, 설명, 예시, 실패 과정, 검증 상태, 출처를 보존.
- 현재 컨텍스트에서 접근하지 못한 대화는 읽었다고 주장하지 않음.
- 민감 정보 확인 후 sessions/에 고유 파일명으로 저장.
- 위키 영역은 직접 관리하지 않음.

완료 기준: 두 에이전트에서 샘플 학습 노트 저장 가능.

## 5. Obsidian 플러그인 설치 지원

- Karpathy LLM Wiki의 릴리스 파일·라이선스·지원 Obsidian 버전 검토.
- 호환성을 확인한 버전 고정 및 다운로드 검증 방식 결정.
- 사용자 동의 후 설치, 기존 파일 보존·백업.
- Obsidian 앱 설치, 플러그인 활성화 및 모델 인증은 수동 안내.

완료 기준: Windows Obsidian에서 샘플 노트를 수동 ingest하여 위키 생성 확인.

## 6. npm 래퍼와 배포

- Go linux/amd64 바이너리 빌드.
- 메인 npm 패키지와 linux-x64 바이너리 패키지 구성.
- optionalDependencies 버전 고정, os/cpu 제약 지정.
- 래퍼는 인자·표준 입출력·종료 코드만 전달. shell 문자열 조합 금지.
- 누락된 플랫폼 패키지 오류 안내.
- npm pack 기반 로컬 설치 검증 후 공개 배포 여부 결정.

완료 기준: WSL에서 npx 실행 시 Go 마법사로 연결되고 Ctrl+C 및 종료 코드 정상 처리.

## 7. 실제 환경 종단 간 검증

- WSL에서 초기 설정.
- pi/Codex에서 학습 노트 저장.
- Windows Obsidian에서 동일 파일 확인 및 ingest.
- 재설치 및 기존 Vault 연결 시 데이터 보존 확인.

현재 개발 환경에서의 단위 테스트와 사용자의 Windows/WSL 실제 검증을 구분해 기록.
